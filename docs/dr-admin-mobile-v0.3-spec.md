# Админка стола ДР — мобильное мини-приложение

**Версия:** 0.3  
**Статус:** Согласованная UX-логика; технические интеграции требуют уточнения  
**Дата фиксации:** 26.10.2026  
**Объект:** Мобильный веб-интерфейс для аниматора  
Назначение документа: функциональная и визуальная спецификация последнего согласованного интерактивного прототипа. Документ не утверждает, что описанные экраны или состояния уже реализованы в действующем приложении.


## 1. Назначение и границы

Приложение позволяет аниматору самостоятельно проводить праздник по четырем этапам с телефона. Администратор парка заранее подготавливает оборудование, выбирает и загружает тему. Аниматор не выбирает проект, билд или игровую тему.

| Входит в объем v0.3 | Не входит в объем v0.3 |
| --- | --- |
| Четыре этапа праздника; инструкции; запуск и управление роликами; запуск игрового блока | Выбор и загрузка проекта, билда и темы; конфигурация проекторов |
| Переключение этапов через меню и индикатор прогресса | Определение личности аниматора и привязка к комнате; QR-коды и авторизация |
| Светлая/темная темы; числовая и цветовая индикация; защита от повторных запусков | Управление несколькими комнатами; управление отдельными мини-играми |

В интерфейсе отображаются только назначенная комната и подготовленная тема (если соответствующее поле будет предоставлено системой). Эти значения доступны для просмотра, но не редактируются аниматором.


## 2. Экраны и структура интерфейса


### 2.1. Экран текущего этапа

1. Шапка: «Праздник ДР»; подпись с номером комнаты; кнопка «Этапы» справа.
2. Строка числовой индикации: «ЭТАП N ИЗ 4» и текстовый статус («Готов к запуску», «В процессе», «Остановлено», «Завершено»).
3. Четыре горизонтальных сегмента прогресса: один сегмент на каждый этап; каждый сегмент интерактивный.
4. Крупная цветная карточка: тематическая иконка и название этапа внутри карточки (без дублирующего большого заголовка ниже).
5. Контекстный информационный блок: инструкция до запуска либо текущий статус/следующее действие.
6. Основная кнопка управления. Дополнительные кнопки появляются только в соответствующих состояниях.


### 2.2. Экран «Все этапы»

Открывается кнопкой «Этапы» из шапки. Содержит четыре строки с иконкой, названием и статусом каждого этапа. Нажатие открывает экран выбранного этапа без отправки команды запуска. Кнопка «Закрыть» возвращает к выбранному этапу.

В демонстрационном прототипе на этом экране есть «Сбросить демонстрацию». В рабочем приложении этой служебной кнопки быть не должно.


## 3. Этапы и пользовательские тексты

| № / ID | Название этапа | Инструкция до запуска | Основная кнопка |
| --- | --- | --- | --- |
| 1 / stage_1 | Знакомство с Лисом и злодеем | Собери детей за столом. Когда все будут готовы, запусти знакомство с Лисом и главным злодеем. | Начать знакомство |
| 2 / stage_2 | Возвращение в комнату | Приключения в парке подошли к концу? Вернись с детьми в комнату, рассади всех за столом и запусти приветствие Лиса. | Запустить приветствие |
| 3 / stage_3 | Приключение на столе | Собери детей вокруг интерактивного стола и начни игру. Мини-игры будут сменяться автоматически. | Начать игру |
| 4 / stage_4 | Поздравление именинника | Собери детей за столом. Когда все будут готовы, запусти финальное поздравление Лиса. | Запустить поздравление |

Названия, инструкции и кнопки соответствуют прототипу v0.3. Технические названия команд существующей админки не показываются аниматору.


### 3.1. Соответствие существующим командам (только для интеграции)

| Этап | Существующая команда | Характер контента |
| --- | --- | --- |
| 1 | Start Fox | Вступительный ролик с Лисом и главным злодеем |
| 2 | Congratulation | Ролик Лиса после возвращения из парка |
| 3 | Start Show | Единый игровой блок: мини-игры идут автоматически, завершение — победа над боссом |

## 4. Состояния и правила переходов

Для каждого этапа интерфейс хранит собственное состояние. Переключение между этапами не должно автоматически запускать контент и не должно сбрасывать состояние другого этапа в рамках текущей экранной сессии прототипа.

| Код | Статус интерфейса | Пояснение |
| --- | --- | --- |
| ready | Готов к запуску | Показывается инструкция и кнопка запуска |
| playing | В процессе | Ролик воспроизводится либо игровой блок запущен |
| stopped | Остановлено | Применяется к этапам 1, 2 и 4; на проекторах статичная заставка |
| done | Завершено | Показывается итог и переход к следующему этапу (либо завершение праздника) |


### 4.1. Видеоэтапы 1, 2 и 4

| Текущее состояние | Действие | Результат / новое состояние |
| --- | --- | --- |
| ready | Нажать основную кнопку запуска | Запустить ролик с начала → playing |
| playing | Остановить ролик | Остановить воспроизведение, показать статичную заставку → stopped |
| playing | Начать заново | Перезапустить ролик с начала → playing |
| playing | Ролик завершился | На проекторах статичная заставка → done* |
| stopped | Запустить заново | Запустить ролик с начала → playing |
| done | Повторить ролик | Запустить ролик с начала → playing |
| done | Следующий этап (1 или 2) | Открыть следующий этап без автоматического запуска |
| done | Финал этапа 4 | Показать «Праздник завершен!»; реальное закрытие сессии не задано |

* В прототипе завершение имитируется специальной кнопкой. Способ определения фактического окончания ролика в рабочем приложении отложен и не фиксируется данным документом.


### 4.2. Игровой этап 3

| Текущее состояние | Действие / событие | Результат |
| --- | --- | --- |
| ready | Нажать «Начать игру» | Запустить весь игровой блок → playing |
| playing | Прохождение игры | Мини-игры сменяются автоматически; действий по переключению нет |
| playing | Игровой блок завершен | Показать результат → done* |
| done | Нажать «Следующий этап» | Открыть этап 4 без автоматического запуска |

Пауза, остановка и повторный запуск Start Show не подтверждены; соответствующие элементы управления в v0.3 отсутствуют. Состояние stopped для этапа 3 не используется. Способ получения события окончания игрового блока не определен (* в прототипе есть только симуляция).


## 5. Числовая, цветовая и статусная индикация


### 5.1. Номер текущего этапа

Над индикатором прогресса показывается «ЭТАП N ИЗ 4», где N — номер открытого этапа (1, 2, 3 или 4). Номер изменяется при выборе этапа из меню, при нажатии на сегмент прогресса и при переходе «Следующий этап».


### 5.2. Четыре сегмента прогресса

- Каждый сегмент соответствует этапу с таким же порядковым номером: 1, 2, 3, 4.
- Текущий открытый этап — оранжевый сегмент независимо от его статуса.
- Другой завершенный этап — зеленый сегмент.
- Другие незавершенные этапы — нейтральные серые сегменты.
- Касание сегмента только открывает этап; не запускает ролик или игровой блок.
- Визуальная высота сегмента — 8 px; область касания — 44 px по высоте в прототипе.
- Состояние дополнительно дублируется текстом и иконкой: нельзя полагаться только на цвет.


### 5.3. Статусы в интерфейсе

| Состояние | Индикатор у «ЭТАП N ИЗ 4» | В меню «Все этапы» |
| --- | --- | --- |
| ready | Готов к запуску / нейтральный цвет | Не запускался |
| playing | В процессе / синий | В процессе |
| stopped | Остановлено / нейтральный цвет | Остановлен |
| done | Завершено / зеленый | Завершен |

Обозначения состояния не являются данными о реальном состоянии оборудования, пока не реализован обмен событиями между игровым приложением и админкой.


## 6. Элементы управления и защита от ошибок

- Основное действие всегда одно и визуально выделено акцентным оранжевым.
- Для видеоэтапов во время воспроизведения основная кнопка — «Остановить ролик»; вторичная — «Начать заново».
- При статусе stopped основная кнопка — «Запустить заново»; при done появляется «Повторить ролик».
- После завершения этапов 1–3 показывается «Следующий этап». После этапа 4 — сообщение «Праздник завершен!».
- Команда запуска должна быть защищена от случайной двойной отправки (например, блокировка повторного нажатия на время обработки). Конкретный механизм подтверждения выполнения пока не определен.
- Выбор этапа в меню и через полоски не отправляет игровых команд.
- Технические функции выбора проекта, темы и билда отсутствуют в интерфейсе аниматора.

Особенность прототипа: нажатие «Начать заново» в состоянии playing оставляет экран в playing; демонстрационная версия показывает текстовое уведомление о перезапуске. В рабочей версии это должно соответствовать реальной команде перезапуска.

Палитры отражают текущий дизайн v0.3 и являются рабочими UI-токенами. Фирменный оранжевый используется для основного действия; цвета фона и текста адаптируются под светлую и темную темы.

| Поверхность / карточка | #FFFFFF | #1D222B |
| Приподнятый информационный блок | #F7F0E8 | #282F3A |
| Основной текст | #242127 | #F6F2EC |
| Вторичный текст | #6F6561 | #B9C1CB |
| Границы | #EADFD2 | #3C4551 |
| Главный акцент | #FF6A1A | #FF914D |

- Формы: скругленные карточки и кнопки; крупная тематическая иконка внутри цветной карточки этапа.
- Нет дублирующего большого заголовка под карточкой; название этапа и иконка составляют один смысловой блок.
- Оранжевый обозначает главное действие и текущий открытый этап; зеленый — завершенные этапы.
- Цветовая тема переключается вручную в демонстрации; поведение сохранения настройки в рабочей версии не определено.
- В версии v0.3 по умолчанию для демонстрации открывается светлая тема; темная доступна переключателем.


## 8. Демонстрационные функции и производственная реализация

| В прототипе v0.3 | Требование / оговорка для рабочего приложения |
| --- | --- |
| «Сымитировать завершение» | Служебная команда тестового макета; в рабочем интерфейсе не показывать |
| «Сбросить демонстрацию» | Служебная команда тестового макета; в рабочем интерфейсе не показывать |
| Начальное состояние демо: этап 2, этап 1 отмечен как завершенный | Только пример для просмотра переключений; в рабочей версии начальный этап определяется подготовленной сессией |
| Состояния хранятся локально в прототипе | Способ синхронизации, восстановления и хранения состояния сессии не определен |

| Переключение этапа доступно в интерфейсе | Фактическая поддержка свободных переходов может различаться по темам; требуется проверка |

## 10. Открытые технические вопросы

1. Как рабочая админка получает подтверждения запуска, остановки и завершения видео/игрового блока. Проверка отложена.
2. Какие команды остановки, паузы или перезапуска поддерживает Start Show.
3. Как обеспечиваются доступ аниматора к назначенной комнате и права управления (QR-код — идея, не утвержденный механизм).
4. Как сохранять и восстанавливать состояния этапов при перезагрузке страницы или смене телефона.
5. Какие переходы между этапами поддерживаются каждой игровой темой и какие ограничения должны соблюдаться.
6. Каким образом завершается реальная сессия после последнего поздравления.
7. Нужно ли одновременное управление несколькими комнатами и в каком объеме.

До разрешения этих вопросов документ описывает согласованное поведение мобильного интерфейса v0.3, а не полную архитектуру серверной части или игрового приложения.
